# 写作后台使用说明

打开网站 `/admin/`，用原来的 GitHub 账号登录，选择文章、项目、个人动态或网站设置。后台使用固定版本的 Sveltia CMS 0.265.1 原生界面，不加载 Decap 的编辑器增强脚本和样式。

## 正文与媒体

- 正文使用原生富文本编辑器，也可以切换到 Markdown 源码模式。
- 工具栏支持图片、代码块、表格和分割线。表格可以通过原生菜单编辑行列。
- 截图或复制图片后，可在富文本正文粘贴；封面使用原生图片字段，支持选择、上传和粘贴图片。剪贴板权限和可用操作由浏览器决定。
- 封面不再使用之前定制的裁剪控件，需要裁剪时先在系统图片工具中处理，再上传。
- 在文章或项目的“PDF 附件”字段中上传文件、填写显示名称。发布后网站详情页继续提供 PDF 预览与下载。
- 图片和 PDF 保存于 `public/uploads/`，与内容一起提交到 GitHub。

## 公式与文章引用

网站继续支持原来的数学公式和 `[[文章路径|显示标题]]` 引用。例如 `[[astro-content-collections|Astro 内容集合]]`。路径是博客目录下去掉 `.md` 的文件路径，有子目录时需要包含子目录。

公式可用 `$x^2$`、独立的 `$$` 公式块或原有 LaTeX 分隔符。建议在源码模式编写这些语法；后台使用原生预览，不加载自定义 KaTeX 或双链预览，显示效果以部署后的网站为准。

原来的文档引用搜索、不存在时创建、定制 `/` 菜单、编辑器侧栏目录和封面裁剪属于 Decap 增强功能，本次按要求不迁移。引用文章需要在“文章”中单独创建和保存，不会自动创建。

## 文件夹

文章列表沿用多级文件夹结构。编辑文章时使用原生“文件夹”路径选择器，可选择父文件夹或创建新文件夹。`nested.subfolders: false` 保留普通 Markdown 文件格式，移动时只移动当前文件。

移动或重命名文章会改变网址，需要同步检查链接、引用以及相对路径图片；`/uploads/` 下的媒体不受文章移动影响。迁移本身不会重命名现有文件。

## 保存与草稿

Sveltia 原生草稿备份保存在当前浏览器，可在用户偏好中控制。它不等于提交到 GitHub，也不会同步到另一台设备；清理站点数据会丢失本地备份。

点击保存会将内容提交到 `main` 并触发 GitHub Actions。保存成功后仍需等待网站构建和部署，通常需要数分钟；未更新时先看 Actions，不要重复创建内容。

Decap 增强脚本原先保存在 `atlas-writing-drafts` IndexedDB 中的未发布草稿不会自动导入 Sveltia。本次不会清除这些数据；迁移前有未发布内容时，先复制正文或通过旧版后台恢复并保存。旧脚本保留在 Git 历史中。已发布到仓库的文章可直接继续编辑。

## 网站文章目录

长文章仍按正文标题自动生成目录，宽屏位于正文左侧，窄屏可展开。这是网站前台的功能，后台使用 Sveltia 自身的布局和侧栏。
